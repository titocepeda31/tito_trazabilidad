# Roles personalizados: fase inicial

Importar 004_access_roles.sql en maderas7_ttrazabilidad ANTES de desplegar el backend (la autenticación requiere las tablas). No se cambian cuentas ni roles existentes. Menú administrador: Roles y permisos. Crear un rol, elegir permisos de consulta y asignarlo a un usuario no administrador de la misma empresa. El usuario vuelve a iniciar sesión y ve un espacio de consulta independiente. Sin asignación conserva el cajero heredado. Retirar un rol restaura explícitamente los permisos anteriores; no usarlo como forma de revocar el acceso (desactivar usuario en Usuarios).

Las rutas permitidas se enumeran exactamente por método y patrón Slim; cualquier otra ruta se deniega para usuarios con rol personalizado. No se alteran comprobaciones heredadas de administrador, salvo permitir la lectura de cotizaciones con permiso explícito. Los permisos son de alcance empresa, salvo ventas propias. No se permite crear ventas, editar catálogo, aprobar descuentos, exportar, ni asignar sucursales en esta fase. Los roles no pueden desactivarse mientras tengan asignaciones. Cambios registrados y sesiones revocadas; solicitudes en ejecución pueden finalizar. No confundir roles de plataforma con roles de empresa.

Pruebas: crear rol de solo inventario, asignar usuario de prueba, comprobar GET productos permitido y GET ventas/quotes, POST ventas y POST roles prohibidos; modificar permisos y comprobar revocación de sesión y nuevos permisos; probar asignación de usuario/rol de otra empresa y promoción a administrador; confirmar administrador y cajero heredado siguen operando. Probar consulta de ventas propias, cotizaciones y cambio de contraseña. Auditar permisos de escritura y sucursal antes de habilitar.
