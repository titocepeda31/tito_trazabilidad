# Catálogos de origen — fase 1
Respaldar e importar 007_origin_catalog.sql en la base independiente después de 006. Revisar esquema real (BIGINT UNSIGNED de PK, nombres de tablas) antes de importar. Los proveedores anteriores están almacenados como supplier_name en goods_receipts; no se encontró mantenedor separado en el código. La API expone nombres históricos como sugerencias de alta manual sin inferir identificaciones o vincular registros. No se modifica stock, SKU ni historial.

Mantenedores por empresa: fabricantes, marcas con fabricante opcional, proveedores con identificación CL validada o extranjera y campos de contacto. Producto existente: fabricante, marca, modelo y varios proveedores. Se permite origen desconocido. Por ahora una marca tiene un fabricante opcional; si está definido, se exige coherencia con el producto. Cambiar fabricante de marca asociada requiere revisar primero las asociaciones. No hay borrado de catálogos; se inactivan. Los usuarios administradores son los únicos autorizados, los roles personalizados no reciben rutas nuevas.

Pruebas: duplicados, RUT, fabricante ajeno/inactivo, marca incompatible, proveedor ajeno, producto existente e historial sin cambios. Pendiente integración de proveedor seleccionado en nuevas recepciones, códigos y costos por proveedor, seriales y permisos no administrativos. No se han ejecutado SQL ni pruebas de compilación/integración.
