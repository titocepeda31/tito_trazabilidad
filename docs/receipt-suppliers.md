# Proveedores en recepciones
Importar 008_receipt_suppliers.sql después de 007 y antes del backend. Comprobar previamente que goods_receipts.id es BIGINT UNSIGNED; FK requiere el mismo tipo. Nuevas recepciones desde React seleccionan proveedor activo por ID; el servidor toma nombre e identificación del catálogo y registra snapshot en la misma transacción que stock, líneas y asociación producto-proveedor. Los intentos anteriores por supplier_name se siguen aceptando por compatibilidad con clientes y reintentos heredados; no se les atribuye ID automáticamente. El hash de solicitudes antiguas conserva el formato; las nuevas usan ID estable, de modo que renombrar o inactivar un proveedor no rompe el reintento de una compra ya confirmada. No se cambia precio de venta ni costo histórico. Se consulta historial de costos CLP desde las líneas existentes, sin tabla de costos duplicada; máximo 100 líneas por filtro. La pantalla lista solo proveedores activos, aunque la API permite consultar compras de inactivos.

No se ha ejecutado SQL ni pruebas de compilación/integración. Pendiente SKU de proveedor, moneda extranjera y números de serie. No se corrige diseño de catálogos en esta entrega.
