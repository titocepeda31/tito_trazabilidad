# Puntos de venta — fase 1
Respaldar e importar 006_sales_points.sql después de 005 y antes de desplegar. Requiere pos_terminals (migración heredada ya existente). Crear un punto desde el menú Puntos de venta y asignarlo a una sucursal activa. Vincular un terminal registrado a un punto; no cambia su warehouse_id ni la caja. El punto identifica sucursal comercial, no el lugar del stock. Código y sucursal son permanentes; nombre y estado editables. Desvincular terminales antes de desactivar. Desactivar puntos antes de desactivar sucursal.

En ventas normales, crédito y conversión de cotización, si hay terminal vinculado, guardar snapshot dentro de la transacción: punto, sucursal comercial, terminal y bodega de despacho. Sin vínculo no se inventa atribución. Historial de ventas anterior no se rellena. La API de listado y detalle devuelve nombres históricos comerciales. La UI del historial aún no muestra columnas nuevas. No se ha eliminado la dependencia heredada entre caja, terminal y bodega: seleccionar despacho en otra ubicación por operación y permitir puntos sin terminal requiere integración posterior y pruebas de caja, stock, devoluciones y crédito.

Probar alta, código duplicado, sucursal ajena, terminal ajeno, vincular/desvincular, cambio de nombre sin alterar snapshot, venta normal/crédito/conversión, caja sin vínculo y conciliación de stock. No ejecutar migraciones antiguas contra la base original.
