# Unidad comercial por producto y operación — rama de desarrollo
**Etapa catálogo:** respaldo, ejecutar SQL 040 una vez (comprobar 3 protecciones), actualizar backend y frontend. No habilita operaciones UF. La API anuncia capacidad solo cuando la tabla y tres triggers están visibles.
- Empresa: preferencias existentes CLP/UF; se verifica unidad habilitada en servidor.
- Catálogo: alta y edición normales, precio original, base e impuesto, versión y equivalente CLP referencial usando la UF registrada de hoy. Sin modificar operaciones históricas. Los precios CLP legacy conservan compatibilidad; si una ruta legacy cambia un precio CLP, la metadata anterior deja de presentarse como vigente.
- Migración 040: tabla append-only de versiones comerciales y triggers transitorios que impiden insertar líneas UF en ventas/cotizaciones legacy, y alterar su precio CLP fuera de una versión coherente. Requiere comprobar permisos de triggers, rollback y motor MySQL; no está verificado contra cPanel. Un producto UF queda visible en inventario pero no vendible ni cotizable todavía; una cotización antigua de ese producto también puede quedar bloqueada al convertirla. La edición rechaza el cambio a UF si el producto tiene una cotización abierta (draft/sent/accepted/reserved); verificar estos casos y reservas.
- POST /currency/operation-preview: cálculo de referencia para lista mixta, unidad de operación elegida y fecha exacta, tasa y versión por producto, CLP al peso/UF seis decimales. No crea venta, no reserva stock, no aplica descuentos ni define importes fiscales definitivos. Pendiente política de redondeo entre unidad, línea y total.
- Pendiente: selector y preview en interfaces de ventas/cotizaciones; snapshots y validaciones transaccionales para venta directa, crédito, descuentos presenciales/remotos, reservas/series, cotización y conversión parcial, importador activo, devoluciones/DTE/caja/reportes. Evitar revaluar operaciones históricas y no usar precio CLP referencial de UF como precio vigente. Resolver clasificación tributaria con DTE; seleccionar impuesto comercial no crea política tributaria. Revisar permisos de operación y unidad de producto cuando empresa restringe unidades.
- Tests unitarios añadidos, no ejecutados; pendiente pruebas integración y build. No quitar los bloqueos hasta integrar las operaciones. Pruebas de cPanel y del build pendientes.

## Prueba de aceptación del catálogo
1. Verificar respaldo y SQL 040: protecciones_instaladas = 3. Si error de privilegios, no reintentar a ciegas ni habilitar UF.
2. Actualizar backend; verificar GET /currency/settings devuelve catalog_commercial_enabled=true. Antes de instalar, catálogo CLP conserva el formulario previo.
3. Crear producto CLP y producto UF de prueba con códigos distintos; guardar precio final o neto/IVA. Verificar precio original, equivalente de referencia, versión, stock y edición/historial.
4. Verificar que el producto UF no aparezca para agregar en ventas o cotizaciones, y que las rutas antiguas no inserten líneas UF; comprobar venta CLP y conversión de cotización CLP sin cambios. Si hay cotización abierta no se puede cambiar el producto a UF.
5. Verificar importador CLP y recepción existentes; no utilizar para modificar precio UF. No confundir precio de referencia con precio vigente ni clasificación comercial con política DTE.
