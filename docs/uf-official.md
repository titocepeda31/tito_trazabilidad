# UF oficial automática
Fuente: Banco Central de Chile, API BDE, serie F073.UFF.PRE.Z.D. Registrar y habilitar una cuenta en https://si3.bcentral.cl/estadisticas/Principal1/Web_Services/acceso_api.html y obtener el API Key Token. En cPanel, guardar SOLO en configuración privada del backend: variable de entorno TITO_BCCH_API_TOKEN o clave bcch_api_token en backend/private/config.php (archivo real no versionado). Nunca colocar en Vercel frontend, GitHub, ni enviar por chat. Requiere PHP cURL, HTTPS saliente y certificado CA válido.

El panel consulta por fecha; si no hay valor registrado, solicita la fecha exacta a la API mediante POST /currency/uf/sync. Reutiliza el valor de la empresa si existe. Botón de actualización explícita permite consultar de nuevo y, si cambia la fuente o el valor, agrega una nueva versión, preservando las antiguas. No modifica precios, ventas o borradores históricos. La conversión usa únicamente el valor de la fecha pedida; sin tasa no convierte. El respaldo manual requiere referencia de fuente y no se presenta como consulta oficial. Si hay una tasa manual existente, la consulta automática no la reemplaza sin actualización explícita.

Sin SQL nuevo; usa 038. No hay cron: consulta al abrir panel y seleccionar fecha. Futuras cotizaciones/ventas deberán exigir la tasa correspondiente desde el servidor. Validar token, conectividad, datos reales incluidos fines de semana, respuestas erróneas, reintentos, concurrencia, manual vs oficial, aislamiento y frontend. Las pruebas de parser usan fixtures, no certifican la conexión real.

## Sincronización por períodos (28-11-2026)
El Banco Central publica la UF para el tramo 10 de un mes al 9 del siguiente. Referencia: https://www.bcentral.cl/es/web/banco-central/areas/estadisticas/preguntas-frecuentes-estadisticas. GET /currency/uf/coverage permite ver cuántas fechas hay guardadas (incluye respaldo manual). POST /currency/uf/sync-range recibe from, to y refresh opcional: hasta 366 días, desde 2000, hasta el horizonte de publicación potencial del día 9. Solo se almacenan observaciones oficiales OK de fecha exacta devueltas por BDE, no se predicen fechas futuras ni se rellenan huecos. Si no falta ninguna fecha y refresh es false, no se consulta al proveedor. No sobrescribe registros previos; correcciones oficiales explícitas crean versiones. Si falta una fecha al abrir el conversor, se solicita su tramo completo en vez de una observación. El botón por rango permite cargar historial y fechas futuras ya publicadas; se muestra cobertura y fechas faltantes. Si el token caduca, las tasas almacenadas siguen disponibles, pero no hay acceso a nuevas publicaciones hasta renovarlo. Respaldo manual solo para hoy o pasado. Sin cron ni SQL nuevo; requiere desplegar frontend y backend. Pruebas añadidas al parser, límites y cambios de mes/año; probar consulta real BDE de rango, disponibilidad futura, aislamiento, idempotencia y funcionamiento con token ausente en cPanel.

## Tabla de valores guardados
GET /currency/uf/coverage y POST /currency/uf/sync-range incluyen rates: una fila por fecha, última versión por ID, orden ascendente, fuente y fecha de registro. Misma empresa autenticada, máximo 366 días; no consulta al Banco Central para listar. Conteo y fechas faltantes se calculan de los mismos registros. El panel muestra la tabla del rango seleccionado con 15 fechas por página, formato chileno, origen oficial/manual y versión. Se refresca al sincronizar o consultar una fecha. Las versiones previas se conservan en MySQL. Probar consulta sin token, aislamiento, rangos vacíos/parciales/completos, distintas versiones de una fecha, paginación y refresco tras descarga.
